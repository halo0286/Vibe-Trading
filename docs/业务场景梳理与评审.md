## 二、逐场景详细梳理

### 场景 ① 自然语言研究分析

**核心价值**：用自然语言驱动金融研究，无需编写代码即可完成选股、财报分析、新闻舆情研判。

| 维度 | 详情 |
|---|---|
| **入口** | CLI `vibe-trading run "..."` / Web UI 对话框 / MCP `run` tool |
| **LLM 支持** | OpenAI / Anthropic / DeepSeek / Kimi / Gemini / Ollama(本地) / Copilot / OpenRouter 等 13+ provider |
| **核心工具** | `get_market_data`, `get_financial_statements`, `get_stock_news`, `get_research_reports`, `web_search`, `read_url`, `iwencai_search`, `screen_market`, `search_symbol`, `get_stock_profile`, `get_macro_series` |
| **数据源降级链** | tushare → akshare → mootdx → yfinance → 腾讯行情（自动 fallback） |
| **持久记忆** | 跨会话记忆（`memory list/show/search/forget`），支持 CJK slug |
| **技能系统** | `list_skills` / `load_skill`，可加载预置或自定义研究技能 |

**评审：**

| 项 | 评级 | 说明 |
|---|---|---|
| 功能完整性 | ★★★★★ | 覆盖基本面/技术面/新闻/宏观/研报/搜索全链路 |
| LLM 兼容性 | ★★★★★ | 13+ provider + 本地 Ollama，含 reasoning model 支持 |
| 数据可靠性 | ★★★★☆ | 多源降级链设计优秀；但部分源（东财/同花顺）有反爬风险 |
| 安全边界 | ★★★★☆ | fail-closed 工具参数校验、secret scrubbing、shell 工具默认关闭 |
| 局限 | — | LLM 幻觉风险仍存在；复杂量化逻辑仍需代码辅助 |

### 场景 ② 量化因子挖掘与评估

**核心价值**：内置 452 个 Alpha 因子 Zoo，支持因子对比、基准测试、严格防过拟合验证。

| 维度 | 详情 |
|---|---|
| **Alpha Zoo** | 452 个因子（gtja191 系列 + 自定义），中文 docstring |
| **因子对比** | `alpha compare <id1> <id2> ... --sort ir`，IC mean/std、IR、IC-positive ratio |
| **基准测试** | `alpha bench`，全量因子在指定 universe/period 上跑分 |
| **严格模式** | `run_bench_strict()`：同 universe 随机对照 + OOS split，防止因子追踪 market beta |
| **因子分析工具** | `factor_analysis`, `pattern_recognition` |
| **横截面 Alpha** | QuantMind 式 cross-sectional alpha 预测策略模板 |

**评审：**

| 项 | 评级 | 说明 |
|---|---|---|
| 因子覆盖 | ★★★★★ | 452 因子，A股/美股均覆盖 |
| 防过拟合 | ★★★★★ | strict bench + 随机对照 + OOS，业界领先 |
| 可扩展性 | ★★★★☆ | 新增因子只需加 .py 文件 + docstring |
| 性能 | ★★★★☆ | 向量化计算；大规模 universe 可能较慢 |
| 局限 | — | 因子库以价量因子为主，基本面/另类因子较少 |

### 场景 ③ 策略回测与归因

**核心价值**：从自然语言描述到完整回测报告的一站式体验，含风险归因、绩效拆解。

| 维度 | 详情 |
|---|---|
| **回测入口** | CLI `backtest` / MCP `backtest` tool / Web UI / API `/runs` |
| **支持市场** | A股、美股、港股、韩股(KRX)、印度、加拿大、阿根廷、英国、越南、加密货币、期货、基金、外汇、指数（14 类） |
| **回测引擎** | 每市场独立 Engine（执行时 ±30% band、交易税、long-only 约束等本地化规则） |
| **绩效指标** | Sharpe、Sortino、最大回撤、胜率、年化收益、Calmar 等 |
| **风险归因** | `attribution_routes`：Brinson 归因、因子暴露、行业拆解 |
| **风险 X-Ray** | `risk_xray.py`：尾部风险、相关性、regime 切换检测 |
| **期权分析** | `analyze_options`, `analyze_options_payoff`, `get_options_chain` |
| **Run 管理** | `list_runs`, `show`, `retry_run`, `reap_stale_runs` |

**评审：**

| 项 | 评级 | 说明 |
|---|---|---|
| 市场覆盖 | ★★★★★ | 14 类市场，全球主要交易所均覆盖 |
| 本地化精度 | ★★★★☆ | 各市场有独立 Engine + 交易规则；部分新兴市场细节可能不完整 |
| 归因深度 | ★★★★★ | Brinson + 因子 + 行业 + regime，专业级 |
| 可复现性 | ★★★★★ | Run 目录持久化、确定性回放 |
| 局限 | — | 高频/Tick 级回测不支持；滑点模型较简化 |

### 场景 ④ 实盘交易与影子账户

**核心价值**：连接真实券商/交易所，同时提供影子账户模拟验证，fail-closed 安全门控。

| 维度 | 详情 |
|---|---|
| **交易连接器** | 18 个：IBKR、Alpaca、Binance、OKX、Futu、Longbridge、Robinhood、Tiger、MT5、Zerodha、Dhan、Shoonya、Upbit、eToro、Scalable、Trading212、KIS、Toss |
| **MCP 工具** | `trading_account`, `trading_positions`, `trading_orders`, `trading_quote`, `trading_history`, `trading_check`, `trading_connections`, `trading_select_connection` |
| **影子账户** | `run_shadow_backtest`, `scan_shadow_signals`, `extract_shadow_strategy`, `render_shadow_report`——用历史数据模拟策略表现，不消耗真金白银 |
| **安全门控** | fail-closed：无 paper/live 区分的 broker 仅允许 paper + read-only；下单前层层守门；审计日志 |
| **OAuth 集成** | Robinhood/IBKR 等支持 OAuth 授权流 |

**评审：**

| 项 | 评级 | 说明 |
|---|---|---|
| 连接器广度 | ★★★★★ | 18 个连接器，覆盖中美欧韩印加密 |
| 安全性 | ★★★★★ | fail-closed 设计是亮点；shadow account 降低实盘风险 |
| 实盘成熟度 | ★★★☆☆ | 多数连接器为 paper/read-only；真正 live trading 需自行验证 |
| 合规 | ★★★★☆ | 审计日志 + 门控；但用户需自担合规责任 |
| 局限 | — | 部分连接器（如 Robinhood）API 限制较多；中国大陆券商未直接支持 |

### 场景 ⑤ 多市场数据接入

**核心价值**：统一接口访问全球多市场数据，智能降级链保证可用性。

| 维度 | 详情 |
|---|---|
| **数据源** | tushare(A股)、akshare(A股/宏观/外汇)、mootdx(A股/无token)、yfinance(美/港/全球)、pykrx(韩股)、okx/ccxt(加密)、Yahoo(印/加/阿/英/越)、Gildata(A股/token-gated)、QVeris(premium) |
| **数据类型** | OHLCV、财务报表、龙虎榜、大宗交易、北向资金、融资融券、股东户数、限售解禁、ETF 期权、宏观(社融/PMI)、新闻舆情、SEC Filing |
| **缓存** | `VIBE_TRADING_DATA_CACHE` 开关，`~/.vibe-trading/cache` 持久化，staleness guard |
| **PIT** | point-in-time 数据对齐，防前视偏差 |
| **货币处理** | ISO-4217 多币种估值，缺失汇率时 fail-one-source 而非 fail-all |

**评审：**

| 项 | 评级 | 说明 |
|---|---|---|
| 数据源丰富度 | ★★★★★ | 7+ 免费源 + premium 选项 |
| 降级链设计 | ★★★★★ | 自动 fallback，单源故障不影响整体 |
| PIT 正确性 | ★★★★☆ | 核心场景已覆盖；部分边缘 case 可能遗漏 |
| 缓存效率 | ★★★★☆ | 减少重复请求；首次加载仍依赖网络 |
| 局限 | — | 部分源（东财/同花顺）稳定性受反爬影响；实时 tick 数据有限 |

## 四、综合评审结论

### 优势

1. **场景覆盖最全的开源金融 AI Agent**：从研究→因子→回测→交易→推送→多智能体，端到端闭环。
2. **多市场 + 多数据源 + 多 LLM**：全球化视野，不绑定单一供应商。
3. **安全设计领先**：fail-closed 交易门控 + shadow account + secret scrubbing + shell 工具默认关闭。
4. **因子防过拟合**：strict bench + 随机对照 + OOS split，学术级严谨度。
5. **部署灵活**：Docker/pip/MCP/ClawHub 四种方式，个人到团队均可适配。

### 不足与风险

1. **实盘成熟度不均**：18 个连接器中多数仅 paper/read-only，真正 live trading 需用户自行验证和承担风险。
2. **LLM 成本**：Swarm 多 agent + 长上下文研究，token 消耗可观；本地 Ollama 可缓解但模型能力有差距。
3. **数据源稳定性**：部分免费源（东财/同花顺/iwencai）依赖非官方接口，反爬/改版可能导致中断。
4. **文档分散**：wiki + README + 代码注释 + CHANGELOG，缺少统一的"按场景组织"的使用指南（本文档试图弥补）。
5. **中国大陆实盘缺口**：无直接 A股券商连接器（CTP/QMT 等），需通过 IBKR/Futu 等间接参与。
6. **logsystem 集成尚浅**：已接入入口初始化，但 uvicorn access log / 现有 logger 尚未打通脱敏/滚动管线。
